# Guidelines for gribble.dev

House rules the review pass should hold this site to. Everything else comes from the rule set.

## Tone belongs in the chrome, never in the facts

Headlines, empty states and the footer may be playful and nautical. Documentation prose, code
samples, finding text and error messages stay dry and precise. Flag copy that jokes in a place a
reader needs an exact answer.

## Every claim points somewhere

A statement about what Gribble does must be backed by a link to the page that explains it. Flag
marketing sentences that promise a capability with no route, command or doc page behind them.

## No filler, no dead ends

There is no lorem ipsum, no "coming soon", no "click here", and no link that leads to a page
without an onward path. Every page offers a next step back into the docs or the repository.
